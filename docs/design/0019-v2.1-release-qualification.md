### Fault and recovery matrix

SQLite abort triggers exercise both sides of the existing persistence fences;
there are no production fault hooks. The new matrix forces lifecycle creation,
reservation, invocation/usage persistence, text storage/delivery, receiver start
and completion, tool preparation/completion and checkpoint naming failures.
Existing latent tests cover artifact-store-before-delivery and delivered-message
receiver failures, missing payloads, cross-run/identity mismatch and corrupt state.

A receiver-reservation failure exposed a safe recovery gap: controller events
were committed after the preceding checkpoint, making that checkpoint stale.
The new pre-reservation checkpoint preserves those events before reservation.
Six safe matrix boundaries now must resume successfully. Uncertain tool completion
must refuse before provider I/O; no successful mutation is duplicated, committed
usage is not lost, and source files remain unchanged. Unnamed or unvalidated
checkpoints fail closed rather than searching backward across unproven effects.

Live Space Bunny crash/resume and cooperative cancellation also pass:
`live-recovery-v2/validation.json` verifies receipts and traces through CLI readers.
The resumed candidate has the requested file content and exactly one successful
mutation; cancellation has zero mutations. Both preserve source files and valid
agent status. The first live harness watched the end-of-run portable trace and
missed the invocation boundary; its artifacts remain retained. The corrected
harness observes committed SQLite events without changing runtime behavior.

Provider responses lost before usage persistence cannot reconstruct uncommitted
billing. Reserved attempts remain spent; committed usage is never charged twice.
Recomputed model reasoning is not claimed to be deterministic.
